# Stets Home

Дипломный проект: требования и прототип фирменного приложения для управления умным домом компании Stets.

## Описание проекта

К компании RANA.Software обратилась Stets — производитель умных электронных устройств. Устройства Stets уже совместимы со сторонними приложениями умного дома, но этого стало недостаточно: компания разработала программно-аппаратный способ запуска устройств в режиме энергосбережения и готовит к выпуску первую умную лампочку с включением и выключением этого режима. В приложениях других производителей такой функции нет, поэтому Stets заказала собственное приложение **Stets Home**.

Проект выполнен в двух частях. Сначала нужно было проанализировать требования заказчика, смоделировать предметную область и зафиксировать функции первой версии. Затем — собрать прототип интерфейса и показать его заказчику.

**Часть 1. Требования.** Анализ интервью с представителем Stets и потребностей пользователей. Результат: карта пользовательских историй с границей MVP, контекстная и логическая DFD, логическая ER-диаграмма в нотации Crow’s Foot, словарь данных.

**Часть 2. Прототип.** Сборка интерфейса в Figma на дизайн-системе Stets, программа и методика испытаний (ПМИ), видеопрезентация прототипа по шагам ПМИ (до 20–25 минут).

Итоговый артефакт — прототип первой версии приложения, в котором реализованы функции MVP.

## Исследуемый набор данных

Исходными данными проекта были не таблицы для статистического анализа, а материалы заказчика и пользователей, по которым строилась предметная область Stets Home.

В работу вошли интервью с представителем Stets, требования заинтересованных лиц и две персоны. **Михаил**, 30 лет, Санкт-Петербург: новичок в умном доме, делает ремонт, хочет простое мобильное управление светом и энергосберегающими устройствами, плохо переносит сложные интерфейсы. **Алёна**, 35 лет, Москва: опытная пользовательница техники Stets, дома много устройств, хочет одно приложение со всеми привычными функциями и сценарием «нажал одну кнопку — дом работает как нужно».

На этой основе выделен набор функций MVP и смоделированы данные приложения. Логическая модель включает сущности:

- пользователь, дом, пользователь дома, приглашение;
- комната и тип комнаты;
- устройство и тип устройства;
- сценарий и действия сценария.

Для каждой сущности составлен словарь данных: идентификаторы, типы, длина, допустимые значения и примеры (email, пароль, роль, состояние устройства `on`/`off`, заводской `оборудование_id`, расписание сценария и т. д.). Процессы обмена данными описаны на DFD: пользователь отправляет команды управления домами, комнатами, устройствами, сценариями и энергосбережением; устройства возвращают телеметрию; сервис email/SMS доставляет коды восстановления и приглашения. Хранилища логической DFD: D1 «Пользователи», D2 «Дом», D3 «Устройства», D4 «Комнаты».

Эти материалы использовались как единый набор исходных данных для требований, модели данных, прототипа и пунктов ПМИ.

## Цели и основные пункты исследования

Цель проекта — определить требования к первой версии Stets Home, смоделировать процессы и данные предметной области и подтвердить прототипом, что выделенный MVP можно реализовать в интерфейсе и проверить по методике испытаний.

Основные пункты работы:

1. Проанализировать потребности заказчика и персон Михаила и Алёны.
2. Построить карту пользовательских историй и провести границу MVP первой версии: учётная запись, дома, устройства (добавление по QR и ID, включение и выключение), комнаты, режим энергосбережения, сценарии автоматизации, совместный доступ.
3. Описать потоки данных на контекстной и логической DFD.
4. Построить логическую ER-диаграмму в нотации Crow’s Foot и согласовать её со словарём данных.
5. Собрать прототип в Figma по дизайн-системе Stets так, чтобы каждая функция MVP доходила до экрана.
6. Заполнить ПМИ: объект и цель испытаний, требования TR-1 … TR-7, шаги проверки и ожидаемый результат.
7. Подготовить видеозащиту прототипа по сценариям ПМИ.

## Инструкции по развёртыванию и системные требования

Это не серверное приложение, а пакет артефактов и интерактивный прототип. Чтобы «развернуть» проект, достаточно открыть файлы репозитория и ссылки на доски.

### Системные требования

- компьютер или ноутбук с Windows или macOS;
- доступ в интернет;
- браузер Google Chrome версии 70 и выше;
- учётная запись Figma (для просмотра прототипа достаточно режима просмотра);
- для правки диаграмм — [diagrams.net](https://app.diagrams.net/) или приложение draw.io;
- для правки карты историй — доступ к доске Miro;
- Microsoft Word или совместимый редактор для `.docx`.

Размер экрана прототипа: iPhone 13 mini, **375 × 812**.

### Как открыть проект

1. Клонировать или скачать репозиторий.
2. Открыть прототип в Figma по ссылке в файле `Ссылка на Figma.docx` или по адресу выше. Включить режим прототипа (Prototype / Present) и пройти сценарии ПМИ.
3. Открыть карту пользовательских историй в Miro: файл `ссылка на миро.docx` или ссылка выше.
4. Открыть `Диаграммы.drawio` в diagrams.net: контекстная DFD, логическая DFD, ER-диаграмма.
5. Открыть `Словарь данных_.docx` и `ПМИ.docx` для сверки атрибутов модели и шагов испытаний.

### Состав репозитория

| Файл | Назначение |
| --- | --- |
| `Диаграммы.drawio` | Контекстная DFD, логическая DFD, ER-диаграмма |
| `Словарь данных_.docx` | Описание атрибутов модели данных |
| `ПМИ.docx` | Программа и методика испытаний |
| `ссылка на миро.docx` | Ссылка на карту пользовательских историй |
| `Ссылка на Figma.docx` | Ссылка на прототип |

Установка сервера, базы данных и библиотек Python не требуется.

## Планы по доработке

Первая версия закрывает MVP. Дальше имеет смысл развивать продукт так:

- перейти от кликабельного прототипа к рабочей мобильной версии с реальным backend и привязкой к устройствам Stets;
- расширить онбординг для новичков вроде Михаила: подсказки при первом добавлении лампы и настройке дома;
- добавить отчёты по экономии энергии и историю работы режима энергосбережения;
- поддержать больше типов устройств, кроме лампы: розетки, выключатели, датчики;
- усилить совместный доступ: роли, отзыв приглашения, уведомления участникам дома;
- доработать сценарии: геозоны, датчики, цепочки условий, виджет «одна кнопка» для Алёны;
- провести юзабилити-тесты по ПМИ с реальными пользователями и уточнить интерфейс по результатам;
- синхронизировать модель данных словаря с API и уточнить статусы приглашений, сессий и доставки сообщений.

## Вывод по проекту

Stets Home закрывает разрыв, из‑за которого заказчик не мог вывести на рынок лампочку с режимом энергосбережения: у конкурентов не было нужной функции, а пользователям нужно одно понятное приложение.

По интервью и персонам выделен MVP, предметная область описана DFD, ER-диаграммой и словарём данных, прототип в Figma показывает все функции первой версии, ПМИ задаёт способ их проверки. Проект можно демонстрировать заказчику как согласованную первую версию: от требований до проверяемого интерфейса. Следующий шаг — реализация и испытания уже на реальных устройствах Stets.
